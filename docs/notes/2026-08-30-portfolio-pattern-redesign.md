# 포트폴리오 4종 패턴을 학습한 랜딩 페이지 디자인 디벨롭

- 날짜: 2026-08-30
- 범위: `index.html` 전체 (CSS 토큰·컴포넌트 스타일, 히어로 마크업 래퍼, 섹션 내비)

## 무엇을

권나정·백경윤·김보현·정예원 프로덕트 디자이너 포트폴리오(PDF 4종, 총 184p)에서 반복되는 시각 패턴을 추출해 페이지 전체에 적용했다. **섹션 순서(히어로 → 01~10 → 푸터)와 섹션 내부 요소 순서, 본문 텍스트는 그대로**이며, 스타일과 래퍼 마크업만 바꿨다.

## 왜

기존 페이지는 웜 크림지 + 모노 라벨 + 아웃라인 대형 숫자의 "에디토리얼 인쇄물" 톤이었다. 네 포트폴리오는 예외 없이 다음 체계를 공유한다.

1. 쿨 화이트/연회색 그라운드 + 헤어라인 규칙선, 카드에는 1px 테두리와 12px 라운드, 그림자 거의 없음
2. 액센트는 블루 하나. 의미색은 고정 — **빨강 = 문제/VOC**, **초록 = 측정된 결과**, 블루 = 해결/액션
3. 다크 네이비 커버(블루 글로우 + 그리드)로 열고 같은 슬라이드로 닫는 북엔드 구조
4. 스프레드마다 상단에 러닝 탭 내비(현재 위치 볼드), 작은 라벨 → **한 문장 선언형 헤드라인** → 짧은 설명
5. 결과 카드 = 큰 숫자 + 델타 필(−92%) + "개선 전(회색) / 개선 후(초록)" 필 바
6. 인사이트/Key Finding 바(틴트 배경 + 원형 아이콘 + 볼드 리드), VOC↔Key Problem 쌍 카드(중립 vs 핑크), Keep/Problem/Try 회고 카드, 고스트 숫자 넘버드 카드

학습 결과를 반영하려면 팔레트 전환이 불가피했고, 이 전환이 가장 큰 변경이다.

## 어떻게

- **토큰**: `--paper/--surface/--raised` 화이트 계열, `--accent #2563EB`, `--good #10B981`(+bg), `--loss #E5484D`(+bg), `--gate` 앰버 유지. `mark`는 형광 배경 → 블루 볼드 텍스트로 (포폴 4종 모두 마커 강조를 쓰지 않음). 다크모드 3중 정의 블록도 동일 체계로 동기화.
- **커버 스코프** `.cover, .band.dark, .foot`: 토큰 재정의 + `::before` 라디얼 글로우 + `::after` 44px 그리드(마스크로 페이드). 히어로를 `hero-cover`(다크)와 `hero-base`(화이트: 시작 조건·스탯)로 분리.
- **러닝 섹션 내비** `.subnav`: 탑바 아래 10개 섹션 링크, 스크롤 스파이로 `aria-current` 지정. 이를 위해 id가 없던 섹션에 `speed/zero/filter/method/curriculum/fit/faq` 부여.
- **섹션 헤드**: 아웃라인 대형 숫자 → 좌측 좁은 컬럼의 작은 모노 인덱스(`01 /10`) + 다이아몬드 불릿 라벨 + 헤드라인(max 26ch).
- **02 비교**: 행 → 2열 결과 카드. 델타 필(−92 / −86 / −78%, 로고는 "비교 없음")을 `.lbl` 옆에 추가(기존 수치에서 산출). 트랙을 회색 필로, "이 방법"을 초록으로.
- **05 케이스**: 3열 카드, 증거 이미지를 하단 고정(`margin-top:auto`), verdict를 블루 인사이트 바로. "한계" 콜아웃은 `.warn`(빨강) 변형.
- **04 회고 스트립**: 카드 위에 `PROBLEM` 모노 라벨(CSS `::before`).
- **07 커리큘럼**: 2열 카드 + 우하단 고스트 숫자(`.lesson-no`). `.lesson > div:not(.lesson-no)`로 겹침 버그 방지.
- **08**: fit 블루 틴트 / unfit 핑크 틴트 카드. **09** FAQ는 인덱스 리스트 행 유지. **10** 준비물 3열 카드 + 클로징 헤드라인에 화이트→라이트블루 그라데이션 텍스트.
- **메타 블록**: `.deckmeta`에 `Case / 기간 / 인원 / 실작업` 라벨(`<small>`) 추가 — 포폴 커버의 "프로젝트 기간 / 참여 인원 / 기여도" 블록 대응.
- 뷰포트 메타(`width=device-width`)가 없어 추가. 아티팩트 래퍼 밖(배포 환경)에서도 모바일 레이아웃이 적용되도록.

검증: Chrome 헤드리스로 1440px 전체와 390px(iframe 프레임, 헤드리스 최소 창폭이 485라 직접 렌더 불가) 전체를 캡처해 확인. 페이지 레벨 가로 오버플로 없음(`scrollWidth == clientWidth`).

## 2차 수정 — 판매 페이지 관점으로 워딩 전환 (같은 날)

- 03 섹션의 "여기까지 오면 사람이 할 일이…" 패널과 문장 패턴 3행(`.pull`, `.patterns`, 캡션) 삭제. CSS는 남겨둠(재사용 대비).
- 페이지 전체 워딩을 "제 작업 보고"에서 **"수업 후 고객이 가져가는 것"** 관점으로 재작성. 원칙: 헤드라인은 2인칭 결과 문장, 케이스 수치는 근거로 강등, 1인칭 서술("제가…", "만들었습니다") 제거.
  - 히어로 리드·메타(형식/기간/대상/증거 케이스)·"필요한 것 / 필요 없는 것" 카드
  - 02 "3주 걸리던 일이 사흘 안에 손에 들어옵니다", 03 "외주로 넘기던 것까지 당신 손에서 나옵니다", 04 "이 페이지의 숫자는 전부 실제 작업 기록입니다", 05 "AI 결과물을 쓸지 말지 즉시 가리는 눈이 생깁니다"
  - 회고 카드·한계 콜아웃은 남기되 각 항목을 "수업에서 어떻게 해결되는가"로 마무리
  - 탑바 CTA "수업 시작하기", 서브내비 라벨 동기화
- 히어로 메타 블록은 커버 상단 → 스크린샷 아래 커버 하단으로 이동. 스크롤 스파이의 `scrollIntoView`가 뷰어 스크롤을 붙잡던 문제는 `.subnav.scrollLeft`만 조정하도록 수정.
- 페이지에 신청/연락 수단이 없어 CTA는 모두 준비물 섹션(#start)으로 향함. 연락처가 정해지면 탑바·CTA 밴드·클로징 버튼 3곳을 바꾸면 됨.

## 3차 수정 — 보고서 요소 전면 제거, 세일즈 페이지로 (같은 날)

사용자 지시: "보고서적인 것은 모두 빼고, 세일즈의 관점에서 작성". 섹션 10개의 순서와 번호는 유지.

- **제거**: 히어로 메타(형식/기간/대상/케이스), "필요한 것 / 필요 없는 것" 카드, 02 타임라인 SVG·자체 산정 콜아웃·120시간 산정표, 04 세션 로그·일차별 차트·표·회고(PROBLEM) 카드, 05 "솔직하게/한계" 콜아웃, 푸터 데이터 출처 문단, 차트 툴팁·`DAYS` 스크립트.
- **04 교체**: `id="real"` → `id="how"` "수업은 이렇게 진행됩니다" — 1:1·당신 프로젝트 / 매주 한 단계+통과 조건 / 판단은 당신·손은 AI / 도구가 바뀌어도 남는 순서. 새 컴포넌트 `.hows/.how` 추가. 모든 문장은 페이지에 이미 있던 주장(1:1, 6주, 통과 조건, 도구 무관)만 사용.
- **05 재구성**: "되돌아온 사례 3건" → "6주 뒤 당신 파일에 남는 세 가지 기준"(원칙 / 접근성 대비 / 감사 수치). 이미지·verdict는 유지, 태그·헤드라인·본문을 기준 설명으로.
- **02**: 비교 카드 4개 + 합계만 남기고 바 라벨을 "손으로 / 이 순서로"로, 한 줄 캡션으로 산정 기준 고지.
- **FAQ**: "이 케이스는…", "8일로 늘어난 이유" 등 케이스 서술 제거. **10** 클로징·버튼, **푸터** 한 줄 출처로 축약. 히어로 고스트 버튼은 커리큘럼(#curriculum)으로.
- CSS에는 제거된 컴포넌트 규칙(`.deckmeta .startbox .log .chart .admits` 등)이 남아 있음 — 소스 이식 시 함께 정리해도 됨.

## 5차 수정 — 캡처 이미지 → Figma 벡터(SVG) 직접 추출 (같은 날)

사용자 지시: "캡처한 네모 말고 피그마에서 도형을 따다가 넣어" (미관·화질 문제).

- **추출 경로**: REST 토큰이 Figma 측에서 `Token expired`(직접 `/v1/me` 호출로 확인)라 `download_figma_images` 불가. 데스크톱 MCP `use_figma`에서 `node.exportAsync({format:'SVG', svgOutlineText:false})`로 뽑고, 툴 결과가 20KB에서 잘리므로 15,000자 단위로 슬라이스해 반환받아 재조립. 플러그인 샌드박스에는 `fetch`가 없어 로컬 업로드 서버 방식은 불가.
- **노드**: Mascot 포즈 6종(`1:2792/2813/2831/2851/2877/2898`), WeatherIcon 세트 `1:1724`, CalendarCell 세트 `1:2431`(inside-stroke 마스크로 48KB → 동일 지오메트리로 단순화해 재작성), EntryCard 변형 3종(`1:2020/2058/2096`), 레퍼런스 스캔표 `1:30`, 원칙 8개 `1:111`, Ink `1:572` + Accent `1:626`(하나로 합침), EmptyState 세트 `1:2262`(마스코트를 `<use>`로 공유해 축약).
- **적용**: `scratchpad/fig/svg/*.svg`를 `build_svg.py`로 인라인 삽입. 03 갤러리는 `.gallery-svg`(6열 벤토: 마스코트 3 · 날씨 3 · 캘린더 2 · 카드 2 · 스캔 2), 06 플레이트는 `.plate.vec`에 인라인 SVG, `viewBox`를 잘라 읽히는 부분이 플레이트를 채우도록(스캔 `0 0 560 372`, 원칙 `0 81 640 491`, 토큰 `0 0 544 510`, 빈 상태 `30 30 760 460`). 04 화면은 히어로용 2x PNG(`--img-home/--img-entry`)를 재사용.
- 텍스트는 아웃라인하지 않고 `<text>`로 두어 페이지 폰트를 씀 → Google Fonts 링크에 `Gowun Batang` 추가. base64 JPEG 6장 제거로 902KB → 428KB.
- 갤러리 교체 스크립트가 03/04 섹션 경계(`.wrap` 닫기·`<section id="how">`·sec-head)를 삼킨 사고가 있어 수동 복구함. 태그 균형 검사(div/section/figure/svg) 통과.
